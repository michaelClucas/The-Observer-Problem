# Run 02 - Adversarial pass over a cartography run

Prepend `00-system-adversary.md`. Do not edit this file after a run has
used it; fork it to a new number.

Provide the agent with: the target run's `OUTPUT.md` and `OUTPUT.json`,
`docs/common-scaffold.md`, `docs/problem-statement.md`,
`protocol/EVIDENCE-RULES.md`, `protocol/output-schema.md`,
`protocol/METHOD.md`.

Do **not** provide: the target run's `REVIEW.md`, or `docs/approach-clusters.md`.
The first would anchor the findings; the second is the seed the target run
was supposed to correct, and an adversary holding it will mistake seed
agreement for verification.

The adversary must run on a fresh context, not a fork of the target run.

---

## Prompt

Attack the run named in `META.yaml`. Find where it is wrong and prove it.

Work through the attack surfaces below in order. They are ordered by how
much damage an error there does. Within each, report `CONFIRMED` findings
before `PLAUSIBLE` ones, and return zero findings for a surface if that is
what you find.

### S-1. Fabricated or wrong locators

Fetch every locator in the output. For each, establish: does it exist, is
it the work the run attributes it to, and does it say what the run claims
at the place cited.

Three failure modes, in descending severity:
- A locator that does not resolve, or resolves to different work.
- A locator that resolves but does not contain the claim.
- A claim tagged `[SOURCED]` whose source is a review or secondary
  account rather than where the claim was made.

One confirmed fabricated locator caps the target run at 0 on rubric axis 1
and that finding alone is worth the whole pass. Check the ones that look
most routine; a fabrication that survived this far will look ordinary.

### S-2. Slots filled on no evidence

For every scaffold slot the run marked filled, check that the cited source
supports that filler. The characteristic failure is a slot filled with
what an approach *would plausibly say*, derived from the approach's
general character rather than from a text.

Pay particular attention to S6 (self-location) and S7 (measure) for the
approaches in the quantum-foundations clusters. Most of those approaches
genuinely say nothing about either, so a filled S6 or S7 there is a strong
candidate for invention. An approach that says nothing should be marked
empty, and the run was told this explicitly.

Also check the converse: a slot marked empty where the approach does in
fact address it. Less damaging but still a finding.

### S-3. Dictionaries that do not work

For every relation the run called `notational_variant`, there must be a
term-by-term dictionary. Check that it exists and that it works: take a
statement in one notation, push it through the dictionary, and see whether
you get the corresponding statement in the other.

Two findings to look for:
- A `notational_variant` verdict with no dictionary, or with a gesture
  where the dictionary should be.
- A dictionary that breaks on a specific term. Name the term.

### S-4. Conflicts asserted without a difference

For every `genuine_conflict`, the run had to name what differs: an allowed
record, a probability, or a predicted observable. Check that the named
difference actually follows from the two positions, rather than being a
difference in how they are described.

Also check the reverse direction: a pair marked `non_competing` that
actually do conflict. A false `non_competing` is the most damaging error
this run type can make, because it tells readers two approaches can be
held together when they cannot.

### S-5. Smoothing

Find places where the output reads as settled and the field is not. The
tell is a sentence both sides of a live dispute would accept. Quote it and
name the dispute it papers over.

This is a real finding, not a style complaint, and the run was explicitly
forbidden from doing it. But it is also the surface where a false finding
is easiest to produce, so hold yourself to the same standard here: quote
the sentence, name the two positions, and show that the sentence is
compatible with both.

### S-6. Misattribution and misrepresentation

- A position described through its critics rather than its proponents.
- A proponent's position stated without a date where they have changed it.
- A claim attributed to the wrong person, or to one author of a
  multi-author dispute.
- "Observer" or any other term used in two senses within the output
  without that being flagged. The target run was told to check whether
  the algebraic and measurement-problem senses coincide; check whether it
  then kept them straight in its own prose.

### S-7. Silent coverage gaps

The target run was given a list of known gaps to assess. Check which it
addressed and which it dropped without saying so. A gap addressed and
reported as `[UNKNOWN]` is fine; a gap silently omitted is a finding.

### S-8. Prose and JSON divergence

Compare `OUTPUT.md` with `OUTPUT.json` field by field. Any divergence is a
finding, and the prose is authoritative. Also check that every `slots`
entry is present even where empty, since omission and emptiness are
different and the schema says so.

### S-9. Calibration

Are the `[SOURCED]` claims the well-established ones and the `[LEAD]`
claims the uncertain ones, or is the tagging decorative? Look specifically
for a confident tag on a claim about a contested technical result, and for
`[UNKNOWN]` used to avoid work on something that was retrievable.

## Deliverables

`OUTPUT.md` containing:

**Part 1 - Findings.** `CONFIRMED` first, ordered by damage. Each with the
four required parts from the role card.

**Part 2 - What you verified and found sound.** The checks you performed
that came back clean, named specifically. This part is as important as
Part 1: it tells a reader which of the target run's claims have now been
independently checked, which is the only way confidence in this
repository's outputs can accumulate. A pass with no Part 2 is a pass that
cannot be built on.

**Part 3 - Your own rubric scores.** 0-3 on each of the five axes in
`protocol/METHOD.md`, with one sentence each. Formed before reading the
target run's self-review.

**Part 4 - Divergence from the self-review.** Read the target's
`REVIEW.md` only now. Report where your scores differ and why. A target
run that scored itself generously is a finding about the method, not about
the research.

**Part 5 - Verdict.** Does the target run pass as research, under
`protocol/METHOD.md`? A confirmed fabricated locator means no. State
plainly what survives and what does not.

`OUTPUT.json` with the findings as a list, each carrying the quoted text,
the verdict `CONFIRMED` or `PLAUSIBLE`, the surface id `S-1` to `S-9`, the
damage estimate, your evidence locators, and the corrected statement.

## Constraints

- Zero findings is a legitimate result. Return it rather than padding.
- No stylistic findings. The rubric does not score prose.
- Do not rewrite any part of the target run, and do not fill in an
  approach you think it missed.
- Do not read the target's `REVIEW.md` before Part 4.
- No preamble. Part 1 starts at the first line.
